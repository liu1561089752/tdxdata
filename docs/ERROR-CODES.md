# 错误码与失败性质判定

> 本文与 `tdxdata/errors.py` 的**模块 docstring** 是同一张表的两份呈现：
> 代码里那份是"改归属时先改的那份"，本文是给人看的同一内容。
> 两处若不一致，以 `errors.py` 为准并同步本文。
>
> 纪律：本库**不新造含糊异常类**。任何错误码都落到既有类上，
> 归属一旦确定就写进 `errors.py` 的对照表，不在调用点临时发明。

## 1. 错误码 → 异常类对照表

| 错误码 / 形态 | 含义 | 归到哪个类 | 判据 / 怎么识别 | 说明 |
|---|---|---|---|---|
| `-1002` | ctl 或参数**形态**错 | `ParamError` | 回包里出现 `-1002` | 管的是"形态"，不是"值查不到"；且**只在非空请求体时可靠** |
| `-1005` | 命令在、**执行失败** | `ServerError` | 回包里出现 `-1005` | 命令本身是存在的，是这次执行挂了（`ServerError` 类 docstring 另列的同类码归属不变） |
| `104` | 本版本 App **未实现**该命令 | `NotSupportedError` | 回包码 `104` | 与"目录里标 `dead` 的命令前置拦截"配套：一边靠实测回 104、一边靠目录提前拦，判的是同一件事 |
| `20000` | 服务端**门控 / 拒绝** | `ServerError` | 回包码 `20000` | 语义是"**命令在**，服务端拒绝执行"——既不是参数错，也不是能力缺失 |
| `-7201` / `-7202` | 交易类命令需要**真实账号上下文** | `NotSupportedError` | 回包码 `-7201` 或 `-7202` | 本库不做交易，故归"能力不可用" |
| **空骨架** | 查询**执行了**但筛不到实体 | `EmptyResult` | `ColDes` 全是 `N001..N00N`、**没有** `ColName`、`Content` 是空数组 `[]` | ⚠️ **空骨架 ≠ 命令坏**：命令可执行、参数被接受，只是这次没有命中的实体。消息里必须写清这一点，**不许**说成"接口不可用" |
| 空请求体时的 `ctl` | 填错 ctl 服务器也**不报** `-1002` | （不映射到任何异常） | 空 body + 错 ctl → 服务端**静默返回空包/空表**，不报错 | **不能**用"没报 `-1002`"反证 ctl 填对了。要判 ctl 对不对，只能看有没有数据 |

## 2. 怎么快速判断一次调用失败的性质

只问三个问题，顺序别换 ——

```
① 通道通不通？
     ConnectionFailed / Timeout / RateLimited  → 传输层问题，跟命令本身无关
                                                 （退避、换机重试；不要改参数）
② 命令/能力存在吗？
     NotSupportedError（104 / -7201 / -7202 / 本库未实现）  → 能力不存在
     OutOfScope（标的不在本数据源证券表里）                → 换数据源
③ 执行成功了吗？
     ProtocolError      → 回包畸形/解压失败，需要抓包，先别怀疑参数
     ParamError(-1002)  → 我这边填错了（ctl 或参数形态）
     ServerError(-1005 / 20000) → 命令在，服务端执行失败/拒绝执行
     EmptyResult / NoData       → 命令**跑通了**，这一次没数据（含"空骨架"）
```

### 三态对照（用户视角）

| 现象（异常） | 一句话性质 | 下一步该做什么 | 不该做什么 |
|---|---|---|---|
| `EmptyResult` / `NoData` | **没数据**：通道通、命令对，这次筛不到 | 换参数 / 换日期 / 换标的再试 | 别换接口，别报"接口坏了" |
| `ParamError` | **参数错**：我这边填错了（ctl 或参数形态） | 改 ctl 或修请求体形态 | 别退避重试，重试一万次也一样 |
| `NotSupportedError` / `OutOfScope` | **能力不存在**：这件事根本做不了 | 换接口；或换数据源（`OutOfScope`） | 别改参数硬试，别用它当"今天没数据"的理由 |

### 两个最容易搞错的边界

1. **空骨架 vs `-1002`**
   `-1002` = 请求**形态**就不成立（包都没让服务端认下来）；
   空骨架 = 请求**成立并执行了**，只是零命中。
   把空骨架归成"接口不可用"是错误归因 —— 会让人去换接口，而真正该换的是筛选条件。

2. **`-1002` 能不能用来验 ctl**
   **不能。** 只有**非空请求体**时，`-1002` 才是 ctl / 参数错的可靠判据；
   **空 body 时 ctl 填错是沉默失败** —— 服务端不报错，只回空。这是本库最难自查的一类 bug。

## 3. 与解析层的关系（顺手提醒）

解析层另有一个"看起来像没数据、其实是自己丢数据"的坑：
`datacenter.call_raw()` 返回的是**已切好的 `list[bytes]`**，
**不要再 unwrap / 不要再切帧**。二次解包会让**本来能出数据的好命令**表现为永远为空
（历史上据此误判过 57 条命令）。详见 `tdxdata/_engine/datacenter.py` 里
`call_raw` / `decode_json` / `parse_resultset` / `parse_tables` 的 docstring。
